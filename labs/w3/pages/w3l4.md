Every HTTP request is answered in-process: the daily bars, the model's price row and the judge's replies (the recording or edits of it). The keys are fakes.

They are in the chapter, [§4 The P1 judge and `tr grade --judge`](https://scout.edgelab.one/learn/ai-engineering/week-3/#4-the-p1-judge-and-tr-grade---judge-2-h-0). [Concepts](concepts.md) has the short version.

**The data.** Journals of closed FAKEA theses, built by [`tools/fakea.py`](../tools/fakea.py) `journal_of` in a temporary folder: the same trade as labs w3l2 and w3l3, one thesis per arm asked for, closed and graded on session 2026-11-19 unless a check says otherwise (one check grades them in the reverse of the order written). Judge request i gets reply i: the recorded pass ($0.005163 in its run file), a reply with no verdict (paid the same), or an HTTP 400 ($0). One check makes the bars fail once. The budget's estimate of one call's worst case is about $0.043: a $0.045 cap covers one call, a $0.05 cap two (after two paid calls about $0.040 is left).

**What observe can and cannot show.** `observe.py grade` does three things:
- It runs your `grade.to_judge` on a journal of six theses and prints what it lists.
- It runs `grade.judge` twice on four waiting theses: once under a $0.25 cap with four kinds of reply, once under a $0.05 cap with the recorded one. For each thesis it prints the cost and the outcome.
- It runs `tr grade` four times on two waiting theses: plain, `--judge --dry-run`, then `--judge` twice. For each run it prints what was sent and the judge lines.

The replies are fixed: verdicts and what a paid call costs never move. What moves is which theses wait, what each run sends under its cap, and what `tr grade` prints. Observe shows one set of journals; the checks decide.

### w3l4.1 what waits for the judge

**Concept.** The judge takes a thesis once. It must be a champion or challenger thesis (a teacher thesis is never judged), it must have a Grade (the post-trade summary the judge reads needs it), and it must have no `judge_verdict` row yet. Any stored verdict counts, pass or fail: that thesis was judged and paid for once. The list runs oldest first, so a run the cap stops leaves the newest theses for the next run. ### w3l4.2 one cap per run

**Concept.** `tr grade --judge` takes one dollar cap for the whole run (`--judge-max-usd`, default $0.25), not one per call. Each thesis gets `p1_judge` under what the run has left. The budget refuses a call whose worst-case estimate does not fit (`BudgetExceeded`), and that thesis and every later one wait for the next run without trying. Any other failure, such as a reply with no verdict, a failed call or missing bars, stays on its thesis and the run goes on. What a call cost is what the run files it added say they spent, so a reply that judged nothing still counts against the cap. Every thesis `to_judge` lists gets an outcome, in its order. [Run cap](concepts.md#run-cap), [Run file](concepts.md#run-file).

**You edit** the loop body of `grade.judge` ([stub](../exercises/w3l4.2-one-cap-per-run/stub/src/tradingresearch/grade.py)):

### w3l4.3 judge only when asked

**Concept.** The judge is the one paid step of `tr grade`, so it is off by default (ADR-003): it runs only with `--judge`. `--judge --dry-run` lists what it would judge and calls nothing. Plain `tr grade --dry-run` shows no judge part at all. Every line says what its call cost, a call that judged nothing included, and the last line says what the run cost in all. Both are in dollars to the millionth, as the run files have them: one judge call is about half a cent, which cents would round to $0.01. A pass is stored, so a second run never pays for that thesis again. A thesis whose reply held no verdict stored nothing, so it waits for the next run. [Off by default](concepts.md#off-by-default), [Run cap](concepts.md#run-cap).

**You edit** `render_judged` in `grade.py` and the end of `cmd_grade` in `commands/grade.py` ([stub](../exercises/w3l4.3-judge-only-when-asked/stub/src/tradingresearch/grade.py), [stub](../exercises/w3l4.3-judge-only-when-asked/stub/src/tradingresearch/commands/grade.py)):

```python
def render_judged(judged: list[Judged], *, dry_run: bool, max_usd: float) -> list[str]:
    """One line per thesis (verdict and cost, or why not judged), then the count and the run's cost in dollars."""
    if not judged:
        return ["judge: nothing to judge (no graded champion or challenger thesis without a verdict)"]
    # TODO(w3l4.3) each judged or not-judged line shows what its call cost, a call that judged nothing included, and
    #   the last line what the run cost in all: in dollars to the millionth, as the run files have it (one judge
    #   call is about half a cent).
    lines = []
    for j in judged:
        head = f"{j.thesis.ticker:<6} {j.thesis.horizon:<5} {j.thesis.thesis_id} {j.thesis.arm:<10}"
        if dry_run:
            lines.append(f"{head}  would judge")
        elif j.verdict is not None:
            lines.append(f"{head}  P1 {j.verdict}: {j.reason}")
        else:
            lines.append(f"{head}  not judged: {j.error}")
    if dry_run:
        return lines + [f"judge (dry run): would judge {len(judged)} (cap ${max_usd:.2f}); nothing judged, no call"]
    done = sum(j.verdict is not None for j in judged)
    return lines + [f"judge: {done} judged, {len(judged) - done} not judged (cap ${max_usd:.2f})"]
```

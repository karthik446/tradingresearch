### w3l3.1 keep the run file

**Concept.** `run_eval` returns the run in memory. The call has already been paid for, and `tr usage` and `tr grade --judge` read what it cost only from its run file. So the run goes into a run file under `data_dir/runs` as soon as it returns, before anything can go wrong with the reply. A call that failed (here an HTTP 400) has no reply to read, so it cannot grade the thesis: that is `CannotGrade`, naming the error code the run recorded and the run file, so whoever reads the error can open it. A failed call is still a call: its run file is the record of it, even when it cost nothing. [Run file](concepts.md#run-file), [CannotGrade](concepts.md#cannotgrade).

### w3l3.2 verdict and score together

**Concept.** The reply becomes three things. The first is the Score `p1_judge` returns: 1.0 for pass, else 0.0, with the verdict as its answer, the reason as its explanation, and a `JudgeNote` naming the judge model, the prompt's sha256 and the call. Unknown is an abstain, which the rubric stores as fail, value 0.0. The second is a ScoreRecord of that score in the journal: P1Judge's id and version, kind `model`, and the trace and span ids of the call it scores. A change to the grader or the prompt then shows in the scores it gave. The third is the `judge_verdict` row that `tr label` and the reports read, which points at the ScoreRecord. The two rows land in one transaction: if the second write fails, the first is rolled back too, and the next run judges the thesis again. A reply with no verdict is your `p1_verdict`'s `CannotGrade`, passed on, with nothing stored. Its cost is already in the run file. [Score record](concepts.md#score-record), [Abstain](concepts.md#abstain).

**You edit** `p1_judge`, from the w3l3.2 TODO to the end ([stub](../exercises/w3l3.2-verdict-and-score-together/stub/src/tradingresearch/evals.py)):

### w3l3.3 refuse before the call

**Concept.** Some theses the judge may not take. A teacher thesis is never judged (ADR-003). A thesis `tr grade` has not graded, because it never entered or has not closed, has no Grade, so there is no post-trade summary for the judge to read. `label.labelable` already refuses both with `label.Refused`, as `tr label` does. `p1_judge` is a grader, though, and a grader that will not grade raises `CannotGrade`. That is the one error `tr grade --judge` reports on a thesis before it goes on to the next one. The refusal carries its reason, so the operator sees why. It comes before the call: no request is sent, no run file is written, nothing is stored, and nothing is spent. [Refusal](concepts.md#refusal).

**You edit** the first line of `p1_judge` ([stub](../exercises/w3l3.3-refuse-before-the-call/stub/src/tradingresearch/evals.py)):

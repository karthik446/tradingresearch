### w2l4.1 P2 as a grader

**Concept.** A grader scores one sample, the whole reply for one ticker and day, and the reply can hold several theses. P2 is binary per run: the run scores 1.0 only if every thesis in it passes, and a 0.0 names the horizons that failed, in the order the reply gave them (`fails: swing, short`). A run with nothing to check (the reply did not parse, or no item builds into a thesis) is not a 0: the grader raises `CannotGrade`, and the run is left out of the rate. The grader reaches the registry only through `@grader`, and a config can name it only there. [Grader](concepts.md#grader), [registry](concepts.md#registry), [thesis sample](concepts.md#thesis-sample).

### w2l4.2 P3 and P4 as graders

**Concept.** The same shape twice; what differs is what each check needs from the sample. P3 needs the snapshot's last close, because a market_open entry has no price of its own yet. P4 needs the snapshot's levels, its `atr_14` (not `atr_pct`, the ATR as a percent of the close) and the close, in the order `p4_levels_coherent` takes them. Two classes with one id would be a quiet bug: one would replace the other in `GRADERS`, so `@grader` refuses a second class with an id it already holds. [Grader](concepts.md#grader), [registry](concepts.md#registry), [level](concepts.md#level), [thesis sample](concepts.md#thesis-sample).

### w2l4.3 the draft P1 judge

**Concept.** P1 asks whether the mechanism in a thesis's `reason` happened. No rule in code decides that, so a model judges it, and its kind is `"model"`. A judge's verdicts count only once they agree with human labels on closed trades, and there are none until week 3. So the judge is registered, so the experiment configs can name it, but `validated = False`, and `grade` refuses every sample with `CannotGrade` before it looks at the sample or calls anything. The eval run leaves a refused sample out of P1's rate; a 0 would count it, and any other exception would stop the run. [Draft judge](concepts.md#draft-judge), [grader](concepts.md#grader), [registry](concepts.md#registry).

**You edit** `src/tradingresearch/evals.py` ([stub](../exercises/w2l4.3-draft-judge/stub/src/tradingresearch/evals.py)): one new class after `LevelsCoherent`.

- `P1Judge.kind is 'code'. P1 asks whether the mechanism in a thesis's reason happened, which no rule in code decides: a model judges it, and kind 'model' is how a report tells its score from P2-P4's`
- `P1Judge.validated is True. A judge is validated only once its scores agree with outcomes, and there is no closed trade until week 3: until then validated is False, so no report counts its scores` (and the same when `validated` is missing)
- `P1Judge.version is 1 (int). Every grader in the registry carries its version as a non-empty string (LevelsCoherent has '1')`
- `P1Judge().grade(a sample with parse_status 'ok', {}) tried a network or model call. An unvalidated judge costs money and returns scores nobody may count yet: it raises CannotGrade before anything else`
- `P1Judge().grade(a sample with parse_status 'ok', {}) returned Score(value=0.0, ...). A draft judge has no score to give: it raises CannotGrade, so the run is left out of P1's rate instead of counted`
- `P1Judge().grade(a sample with parse_status 'ok', {}) raised NotImplementedError: .... The runner leaves a sample out of the rate only on CannotGrade; any other exception stops the eval run`
- `P1Judge().grade(a sample with parse_status 'invalid_json', {}) raised CannotGrade(output did not parse). The judge refuses every sample for one reason, before it looks at the sample: it is a draft. Say so (the word 'draft'), ...`

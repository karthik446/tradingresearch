**Reading folded in (not exercises):** why an [ablation](concepts.md#ablation) changes one thing at a time; why the primary metric is `claims_valid` and not `all_claims_valid` (0.100 in both week-4 arms, a floor where one bad claim zeroes an analysis); the author's measured result (`claims_valid` +0.005, interval −0.027 to +0.042, without headlines; +0.023, −0.014 to +0.068, without EDGAR; `parsed` held at 1.000); `compare` refusing the first run's block over a section grader scored in one arm only, and the fix; ADR-007's decision that by the rule both sections "go" yet the default does not change, because a rule with no non-inferiority margin can only say "go" when nothing is seen. Read [§5 of the chapter](https://scout.edgelab.one/learn/ai-engineering/week-5/#5-the-ablation-pre-register-run-once-compare-adr-007-25-h-099-at-the-authors-run) and [§10](https://scout.edgelab.one/learn/ai-engineering/week-5/#10-adr-007-in-review-and-what-week-6-does-with-it-05-h-0).

**The data.** The recorded exchange of lab w5l1 in [`data/`](../data/): one analyze-3 request and its reply (11 claims; 7 cite indicator rows, one of them failing `empty_placeholder`, 1 cites a headline), with the price row it was recorded with. The replay runs the config's arms over its 10 tickers on one session, answering every request with that reply.

**What observe can and cannot show.** `observe.py ablation` loads the config, prints its arms, graders and cluster, the pre-registration lines above the first key, then replays it: the requests sent, and per arm each grader's mean and count. It cannot show a real difference between arms: every arm gets the same reply, so the only scores that move are those a drop changes on that reply. Levels and EDGAR have no score in any arm because the reply cites neither.

### w5l2.1 three arms

**Concept.** An [ablation](concepts.md#ablation) removes one part and keeps the rest, so a change in the result belongs to that part. Here each arm is a [drop arm](concepts.md#drop-arm) of the same analyze-3 prompt on the same model: `full` drops nothing, `no-headlines` the headlines, `no-edgar` the EDGAR rows. An arm sets only what differs; the model and the route come from the top of the file.

**You edit** `experiments/context-ablation.toml` ([stub](../exercises/w5l2.1-three-arms/stub/experiments/context-ablation.toml)). The stub has the header, the name, the model, the cap, the tickers and the sessions; it has one grader and no arm, so `experiment.load` refuses it:

```toml
# TODO(w5l2.1) three fixed analyze-3 arms on the same model that differ only in the sections they never see:
#   none, the headlines, the EDGAR rows.
```

**Check and observe:**

```bash
python -m pytest -q -x -p no:cacheprovider -m lab labs/w5/exercises/w5l2.1-three-arms/test_w5l2_1.py
python labs/w5/tools/observe.py ablation
```

| Observe | the config | the $0 replay |
|---|---|---|
| on the stub | `experiment.load refused experiments/context-ablation.toml: ... missing ['arms']` | not run |
| after this exercise | 3 arms, 10 tickers, cluster 'ticker'; full, no-headlines, no-edgar, each claude-sonnet-5.5, analyze-3, fixed; graders `['parsed']` | 30 requests; parsed 1.000 (10) in each arm |

The cluster already reads 'ticker': the loader picks it when the file sets none. Lab w5l2.2 writes it out.

**FAIL messages** (the first is the stub's red run):

- `experiment.load refused experiments/context-ablation.toml: experiments/context-ablation.toml: missing ['arms']`
- `the arms (name, drop) are [...]; expected exactly three: full drops nothing, no-headlines drops ['headlines'], no-edgar drops ['edgar']`
- `the arms (name, prompt, model, provider, mode) are [...]; every arm runs prompt analyze-3 in fixed mode`
- `the arms (name, prompt, model, provider, mode) are [...]; every arm runs the same model, routed the same way, so the drop is the only difference`
- `the replay ran N arms and sent N requests; expected 3 arms of 10 tickers`, `the three arms must run over one dataset`
- `arm <name> (drop [...]) sent a user turn that is not the recorded one masked by its drop`, `arm <name> sent a system prompt that is not analyze-3's`

[Hints](../exercises/w5l2.1-three-arms/hints.md).

### w5l2.2 graders and cluster

**Concept.** The graders are what the result will be read with, so they are chosen before the run: `parsed` (the guard), `claims_valid` (the primary metric), `all_claims_valid` (reported), and the four section graders of lab w5l1, so a loss can be traced to the section it came from. All are [code graders](concepts.md#code-graders): a model grader cannot be trusted on an arm that hid rows from it. The [cluster](concepts.md#cluster) is the unit the paired intervals resample, the ticker: the two sessions of one ticker are not independent.

**You edit** `experiments/context-ablation.toml`, which now has your three arms (no new stub):

```toml
# TODO(w5l2.2) the unit the paired intervals resample, written out, and the graders: the primary and guard
#   metrics, the whole-analysis one, and one per section.
graders = ["parsed"]
```

**Check and observe:**

```bash
python labs/w5/tools/observe.py ablation
```

| Observe | graders | full | no-headlines | no-edgar |
|---|---|---|---|---|
| before this exercise | `['parsed']` | parsed 1.000 (10) | parsed 1.000 (10) | parsed 1.000 (10) |

### w5l2.3 the pre-registration

**Concept.** A [pre-registration](concepts.md#pre-registration) fixes, before any result exists, what is measured and what each result means, so the result cannot choose its own reading. It names a [primary and a guard metric](concepts.md#primary-and-guard-metric) and a rule that turns the primary metric's interval into a verdict. Written as comments above the config's first key, it travels with the file the run reads.

**You edit** the header of `experiments/context-ablation.toml`:

```toml
# TODO(w5l2.3) the pre-registration, written before any paid run: a `Primary metric:`, a `Guard metric:` and a
#   `Rule:` that says when a dropped section stays and when it goes.
```

**Check and observe:**

```bash
python -m pytest -q -x -p no:cacheprovider -m lab labs/w5/exercises/w5l2.3-the-pre-registration/test_w5l2_3.py
```

**FAIL messages** (the first is the run on your w5l2.2 file):

- `the primary metric names '...' ('...'); expected claims_valid`
